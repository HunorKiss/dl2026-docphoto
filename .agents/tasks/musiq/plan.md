## Decisions (with reasons)

1. **Vendor the MUSIQ architecture, do not depend on `pyiqa`.** `pyiqa` imports its whole zoo at `import pyiqa` (timm, einops, transformers, huggingface_hub, lmdb, clip, ...) and pins versions, which on a Kaggle image risks conflicts with torch/numpy (this repo pins numpy 1.26.4). Its MUSIQ also has no train-time path with masks and a token cap. The needed code is small and self-contained: `pyiqa/archs/musiq_arch.py`, `pyiqa/data/multiscale_trans_util.py` and `exact_padding_2d` from `pyiqa/matlab_utils/padding.py` (only torch/numpy). I read them. Vendoring them into `src/musiq.py` (about 300 lines) lets me replace `masked_fill` attention with `F.scaled_dot_product_attention` (memory-efficient, needed for ~960 tokens) and build tokens on the GPU. Weights are downloaded directly from the pyiqa GitHub release (`https://github.com/chaofengc/IQA-PyTorch/releases/download/v0.1-weights/<file>`). I downloaded and inspected them: plain `state_dict`s, 248 tensors, 27,125,825 parameters, keys identical to the vendored layout (`conv_root`, `gn_root`, `block1.*`, `embedding`, `transformer_encoder.*`, `head.weight/bias`), and the sha256 starts with the hash in the file name:
   - koniq: `musiq_koniq_ckpt-e95806b9.pth` (sha256 prefix `e95806b9`)
   - spaq: `musiq_spaq_ckpt-358bb6af.pth` (sha256 prefix `358bb6af`)
   - License: pyiqa's LICENSE on `main` is PolyForm Noncommercial 1.0.0 ("Required Notice: Copyright (c) 2022 Chaofeng Chen"); older releases were S-Lab 1.0 (non-commercial). The architecture is a port of Google's MUSIQ (google-research/musiq). Put a header comment in `src/musiq.py` naming the source files, the licence and "non-commercial, coursework use only", repeat it in the `configs/musiq_koniq.yaml` header, and add one line to README.md (item 8).
2. **Fixed-length padded token sequence with masks, not a fixed native size.** Photos have different aspect ratios (portrait 3:4 mostly, some 9:16 or square). A fixed native size would need letterboxing or cropping, which is what the task wants to avoid. Each sample gets a token sequence: 49 slots for the 224 scale, 144 for the 384 scale, up to `native_max_patches` for the native scale, plus a mask. Within a batch the native segment is trimmed to the longest sample, so short images do not cost padding attention. Stem and embedding run only on valid patches (gather by mask, scatter into a zero tensor), so padding costs no stem compute or memory.
3. **Native cap: `native_max_patches = 768`** (config key `model.native_max_patches`). A 1024x768 portrait page is exactly 32x24 = 768 patches, so the usual photo is never touched. A square 1024 px photo would have 1024 patches; instead of cutting patches in raster order (original MUSIQ truncates and loses the bottom of the page) the native image is shrunk with aspect ratio kept until `ceil(h/32)*ceil(w/32) <= 768`. This is deterministic and identical in training, validation and `predict`. Sequence length is at most 49+144+768+1 = 962 tokens.
4. **Memory.** With SDPA there is no stored 962x962 attention matrix. Rough estimate per sample at 962 tokens: transformer about 0.2 GB, ResNet-style stem on 768 valid 32x32 patches (GroupNorm runs in fp32 under autocast) about 0.3-0.8 GB. Batch 8 in fp16 is therefore estimated at 5-9 GB plus 0.5 GB for weights, gradients and AdamW state, which fits a 16 GB T4/P100. The coder must measure on MPS (item 6) and apply this rule: `est_fp16(8) = 8 * 0.6 * peak_fp32_per_sample + 0.5 GB`; if `est_fp16(8) <= 10 GB` keep `batch_size: 8, accum_steps: 2`, otherwise set `batch_size: 4, accum_steps: 4` (effective batch 16 stays; no code change).
5. **Weights cache on Kaggle: `/kaggle/temp/musiq/`** (exists on Kaggle, not part of the notebook output, so two 108 MB files are not committed with the notebook version). Lookup order for `fetch_weights(name)`: `$MUSIQ_WEIGHTS_DIR`, then `/kaggle/temp/musiq` when `/kaggle/temp` exists, else `~/.cache/musiq`. Download once with `torch.hub.download_url_to_file(url, tmp, hash_prefix=<8 hex>)`, then atomic rename. If the notebook has no internet, attach the two files as a Kaggle dataset and set `MUSIQ_WEIGHTS_DIR` to its folder (same file names). Checkpoints written by `src.train` contain all weights, so `src.predict` never downloads (it builds the model with `pretrained: false`, as `load_checkpoint` already does).
6. **Input representation: a centred canvas with a sentinel.** The dataset returns one tensor per photo, shape `(C, S, S)` with `S = data.cache_size` (1024), the photo centred (`top=(S-h)//2, left=(S-w)//2`) and the rest filled with `-1` (valid pixels are in [0, 1]). `C = 1` (grey, repeated to 3 in the model, as the user asked) or `C = 3` with `model.color: true` (RGB, default false). The model finds the image box from `x[0] >= 0`, so default collate, `x.to(dev)`, `train.py` and `evaluate.predict` need no change, and the existing mirror TTA `x.flip(-1)` is correct as is: the canvas is centred, so flipping it mirrors the box content exactly (the box may move by one pixel; the crop is identical). The model builds the three scales on the GPU: `(x-0.5)*2`, ARP bicubic resize with `antialias=True` (the original uses a Gaussian-antialiased resize; plain bicubic aliases at 1024 -> 224, and blur is what the label measures), 32x32 patches with TF-"same" zero padding, hashed 10x10 spatial index, scale id (0: 224, 1: 384, 2: native), mask. Per-sample Python loop over the batch (B <= 8-32) is fine.
7. **Augmentation:** mirror (probability 1/2) and a crop jitter: remove a random 0..`max_shift` px (16) from each of the four edges of the cache image, which shifts the content and the patch grid without adding grey borders. Never blur or brightness.
8. **Pre-test mapping score -> usability:** headline is a **linear fit (OLS, 2 parameters), clipped to [0, 1]**, fitted on the three training folds and applied to the held-out fold of the repo's `group_strict` 4-fold split (`assign_folds(df, cfg["split"]["column"], cfg["split"]["n_folds"])`); it cannot overfit and is robust to the arbitrary MOS scale. Also report **isotonic regression** (sklearn, monotone, the ceiling for any monotone mapping) as a second column. Pooled out-of-fold RMSE is reported on `eval_ok == 1` rows (the number comparable to 0.1956 / ~0.145) and on all rows. Spearman and Pearson of the raw score against `usability` on all 1841 and on eval_ok rows. Run the grid weights {koniq, spaq} x input {rgb, grey}, because MUSIQ was pretrained on RGB while the pipeline is grey. The ranking tells whether the grey input costs anything.
